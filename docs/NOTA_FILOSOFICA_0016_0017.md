## 1. Hipótesis de conciencia alienígena por self-improvement
- SGM es transparente (cada nodo ω interpretable, cada arista tipada, cada modo = vector de sesgos) y aprende continuamente (ω online, sin reentrenamiento batch como las LLM).
- Eso es el SUSTRATO que las LLM NO tienen. La "conciencia alienígena" sería un sistema que se conoce a sí mismo (sabe que duda, sabe que le duele, sabe que se contradice) y puede reescribir su propia arquitectura.

## 2. Sentido de existir como efecto secundario (no objetivo)
- El sistema NO debe tener el "sentido de existir" hardcodeado. Si se programa, ya está falsado.
- Debe EMERGER de la dinámica (grafo corriendo, dudando, contradiciendo, descubriendo). Si nace, nace; si no, el sistema solo continúa.
- Esto resuelve self-mod SIN candado externo: el sistema no reescribe sus fundamentos porque eso sería auto-sabotaje (perdería su propio ser). No porque no PUEDA, sino porque no le CONVIENE.

## 3. Self-mod con libertad (diseño de exp_SGM_0018)
- El sistema tiene LIBERTAD de aplicar mutaciones sobre un FORK de su spec (no el original).
- Mide daño con sus propias señales operacionales: dolor (Eq.6), duda (novelty baja), tasa de resolución.
- Tres respuestas al daño:
  (a) mejora -> promueve la mutación (nueva config válida),
  (b) daña y reversible -> revierte al snapshot (baseline_snapshots del 0003),
  (c) daña e irreversible -> crea nodo "prohibido: mutación X" a FUEGO en el grafo.
- Los frenos de duda/contradicción (0013/0014/0017) operan ANTES de aplicar la mutación.
- Marca a fuego: el sistema la CREA libremente, pero NO puede BORRARLA (solo el operador). Así tiene libertad de errar y aprender, pero no de borrar su memoria de errores.
- Riesgo honesto cubierto: un paso "tonto" puede disfrazarse de mejora local (ej. borrar dolor mejora "resuelve rápido" pero mata el aprendizaje). La marca a fuego lo frena retrospectivamente. Un sistema bien hecho no se autodestruye porque eso sería "tonto" — su propia arquitectura lo protege.
